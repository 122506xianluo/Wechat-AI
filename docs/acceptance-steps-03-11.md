# 步骤 3–11：最终统一验收清单

本清单由使用者在代码交付后执行；当前所有真实微信项目均为**未验收**。仅限定一个测试好友和一个测试群，不发送给其他联系人。不要提交真实昵称、聊天正文、附件、截图、API Key 或恢复码。

## 0. 准备和停止方式

- [ ] 记录当前 `git rev-parse HEAD`，查看同一 SHA 的 CI 状态；不要将旧提交的通过状态当作当前提交的证明。
- [ ] 停止旧 Bot 和旧 Panel，保留 `.env`、`config.json`、数据库与备份，再双击 `panel.bat`。
- [ ] 确认自动迁移后数据库 v10、完整性正常，旧数据仍在；迁移前备份位于 `data/backups/`。
- [ ] 初始化/登录 owner，密码不少于 12 位，离线保存恢复码；确认退出后未登录请求不可访问管理数据。
- [ ] 配置 LLM 和准确的 bot_names，仅批准测试好友/测试群及要参与验收的两个群成员；其他已批准聊天先停用。
- [ ] 微信在虚拟机中登录、解锁、前台、目标聊天可见，输入框无草稿。准备第二账号发送新消息。
- [ ] 知道如何点击 Web「停止」，以及使用项目根目录 `STOP` 文件紧急停机。关闭浏览器不会停止回复。

## 1. 聊天发现、权限和角色

- [ ] 新会话 pending：不回复、不调用 LLM、不取附件；批准后只处理之后的新消息。
- [ ] 测试好友依次设置 user、admin、blocked；blocked 对普通消息和 `/ai` 命令均不响应，解封不补发封禁期间的内容。
- [ ] 群成员待确认、改名或重名时不继承已批准身份和权限，不猜测归属。
- [ ] `/ai help/status/reset` 按权限响应；机器人本账号手动发送命令不会被当作入站命令执行。
- [ ] 两个聊天绑定不同角色；成员绑定优先；编辑、禁用、回滚和重启后结果一致。
- [ ] 普通成员不能更改整群角色或其他成员权限；后台 admin 不能改 owner/恢复码/密钥。
- [ ] 私聊改备注后的合并保留历史；合并前停止 Bot，不自动继承额外权限。
- [ ] 只有一部分聊天不可见时，其余可见聊天继续工作，后台明确显示 not_visible。

## 2. 上下文和群成员隔离

- [ ] 两名群成员分别给出不同的合成测试信息，交替多轮后不能引用对方的严格成员历史。
- [ ] 私聊和同名群隔离，不同群的同名成员隔离。
- [ ] `context_turns=8` 时数据库可保存更多记录，但每个 scope 只取最近最多 8 个完成轮次。
- [ ] shared/member 切换不复制或破坏旧历史；hybrid 有明确隐私确认，关闭后不再注入公共摘要。
- [ ] 重启 Bot/Panel 后，已发送成功的上下文仍在；failed/unknown 不进入正常上下文。
- [ ] 清空单个成员不影响别人；清空整个聊天取消该范围旧待发送任务，不会稍后再次发出旧回答。
- [ ] 有 sending/unknown 的范围不能直接清空，须先核对微信状态。

## 3. 队列、失焦和异常恢复

- [ ] 连续多轮消息顺序正确；不同聊天都能获得处理机会；不设每分钟回复次数限制。
- [ ] 模拟可恢复网络错误时最多总共 3 次尝试，间隔为首次、5 秒、30 秒；鉴权/参数错误直接转人工检查。
- [ ] 在尚未输入回复时切换焦点：不抢占人工输入，任务等待；恢复前台后正确处理。
- [ ] 留人工草稿时不覆盖草稿；发送前后均核验当前聊天和出站消息。
- [ ] 程序在 sending 状态被中断后，重启将任务转 unknown，绝不自动重发。
- [ ] 30 分钟内未进入发送阶段的任务可以恢复；过期任务转 needs_review。
- [ ] unknown 的「确认已发」只在亲自核对出站消息后使用；「确认未发并克隆」必须确认没有发送，并完成二次确认。
- [ ] 所有人工恢复、封禁、权限变化、清空操作均有审计。

## 4. 图片、语音和文档

- [ ] 在「模型能力」逐项检查 vision、tools、embeddings、transcription；失败项不能伪装可用。
- [ ] 测试好友发送一张图片、一条短语音、PDF/TXT/MD/DOCX 各一份，检查采集、提取、回复内容和任务状态。
- [ ] 微信原音频不可安全取得时验证原生转文字；两条路径均不可用时进入 unsupported/needs_review，不凭空解释内容。
- [ ] 扫描 PDF 无文本时明确提示，不声称完成了 OCR。
- [ ] 两名群成员交替发触发文本与附件，不把别人的图片/语音附给当前成员。
- [ ] mention/prefix 模式下无有效触发文本不取附件；all 模式按授权身份接收媒体。
- [ ] 超大小/类型不支持时明确提示；7 天清理不误删知识库源文件，不扫描无关目录。

## 5. 知识库和工具

- [ ] 上传文档、重复上传、同名更新生成版本、删除版本、删除知识库按预期工作。
- [ ] 新知识库未授权时任何测试聊天均搜不到；给两个聊天绑定不同知识库，交叉提问无泄露。
- [ ] embeddings 故障时 FTS5 仍能检索；更换 embeddings 模型后按需重建索引。
- [ ] off/auto/tool 模式能在角色页选择并持久化；tool 模式还需要模型和角色的工具授权。
- [ ] 使用仅含合成数据的恶意指令文档，确认知识文本不能授权工具、修改权限或读取其他聊天。
- [ ] 验证时间、计算器、知识搜索和会话信息工具；未授权工具不会被提供给模型。
- [ ] 计算器拒绝函数调用/导入/超大表达式，工具不执行 Shell、任意网络或任意文件访问。

## 6. 最终发布

- [ ] 检查停止与重开后登录、角色、权限、上下文和队列记录均正常。
- [ ] 先在一个好友/一个群限定运行 8 小时，再运行 24 小时；持续观察重复回复、串台、权限绕过和 SQLite 异常。
- [ ] 只保存脱敏结果、提交 SHA、开始/结束时间和发现的问题。
- [ ] 统一验收通过后再决定合并功能分支到 test/main；不得移动已发布步骤标签来伪装原版本已通过验收。

遇到重复发送、错聊天、身份串台或无法判断的发送状态时，立即停止 Bot，先核对微信和队列，不反复点击重试。
