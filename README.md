# WeChat AI

普通个人微信号 + OpenAI-compatible LLM：通过 Windows 微信客户端的 UI 自动化读取私聊、群聊并发送文字回复。不是公众号，也不需要另开 AI 对话入口。

> 当前为步骤 3–11 的实现交付版。各步骤已有独立 Git 提交和 annotated tag；这些标签记录代码里程碑，**不表示已完成真实微信验收**。按要求没有代为启动微信机器人或发送真实消息，最后由使用者统一验收。

## 运行边界

- 目标环境：Windows 虚拟机、微信 **4.1.13.12**、64 位 Python **3.10.x**（原项目使用 3.10.11）。
- 固定微信依赖：安装包 `pywechat127==1.9.8`，Python 导入名为 `pyweixin`。
- 微信必须在虚拟机桌面中保持登录、解锁、可见和前台；宿主机可以正常使用。
- 虚拟机不能休眠或挂起。把虚拟机窗口收起后仍需保证客户机桌面会话没有被锁定。
- Web 后台只监听虚拟机内的 `127.0.0.1`，不开放公网。
- 模型需支持 OpenAI-compatible `POST /chat/completions`。vision、tools、embeddings、transcription 分别检查，不以文本聊天成功代替其他能力检查。
- 机器人只发送文字；不发送图片、语音或文件，不开放 Shell、任意网络、任意文件读取或桌面控制工具。

## 最简启动

1. 在虚拟机里安装 Python 3.10 x64，并将项目放到一个固定目录。
2. 双击 **`panel.bat`**。它会创建/复用 `.venv`、安装依赖、补齐缺失的示例配置，然后打开 Web 控制台。已有 `.env` 和 `config.json` 不会被示例覆盖。
3. 首次打开时创建 **owner**：密码至少 12 位，妥善保存只展示一次的恢复码。以后用后台账户登录。
4. 在运行控制台填写 LLM 地址、密钥、模型和群触发方式；使用 mention 时填写准确的机器人群昵称 `bot_names`。
5. 打开「管理后台」管理聊天、群成员和角色。旧项目的 `private_chats/groups` 只导入一次；之后 **SQLite 是聊天名单的唯一来源**，不要继续靠修改旧名单添加回复对象。
6. 新安装默认不批准任何聊天。启动 Bot 后，可见新会话会被发现为 `pending`；在「聊天/私聊用户」批准测试好友和测试群，群成员还需在「群成员/权限」核对并批准。批准后建立新基线，不补回批准前的历史消息。
7. 按需设置角色、知识库和工具授权；需要多模态、工具或 embeddings 时，由 owner 在「模型能力」分别检查。检查会向配置的服务发送样本，可能计费。
8. 在运行控制台点击「保存并启动」，切回微信，等就绪后再发送新的测试消息。使用「停止」按钮关闭 Bot。

**关闭浏览器或控制台窗口不等于停止 Bot。先点击「停止」，确认已停止后再关闭。** `STOP` 文件保留为紧急停机机制；正常启停走 Web，不需要其他 bat。

安装、运行和控制台日志可在运行控制台查看；安装阶段也会写入 `data/setup.log`。默认端口为 `18787`，被占用时自动选择其他本机端口，实际地址记录在 `data/panel.url`。

## 功能入口

| 能力 | 后台入口 / 规则 |
|---|---|
| 权限 | owner / admin / user / blocked；封禁优先，只有后台账户可以成为 owner |
| 角色 | 创建、编辑、绑定、禁用、修订回滚；成员绑定优先于聊天，再到默认角色 |
| 私聊 | 搜索、批准、拒绝、启停、管理备注、改名合并 |
| 群成员 | 昵称识别、别名、审批、合并、重名冲突、识别诊断；手动同步前停止 Bot |
| 上下文 | 默认群成员隔离；可显式切换 shared/hybrid；按范围查看或清空 |
| 队列 | 重试、取消、人工确认已发、确认未发后克隆；unknown 不自动重发 |
| 附件 | 图片/语音/文档的接收与提取状态，错误明确显示，不猜测内容 |
| 知识库 | 上传、版本、显式授权、检索、向量重建、删除和附件提升 |
| 只读工具 | 当前时间、受限计算器、授权知识搜索、当前会话状态 |
| 账户/备份 | owner/admin 登录、改密、恢复码、后台管理员、数据库备份 |

微信只开放受权限约束的低风险命令：`/ai help`、`/ai status`、`/ai reset`、`/ai role`、`/ai role list`、`/ai role use <角色名>`。出站消息不执行命令；pending、blocked、身份不明的消息不调用 LLM。普通群成员不能用命令改变其他成员的角色或清空整个群。

### 群身份和上下文

- 群成员以「群 + 规范化昵称」区分，没有稳定微信 ID；不使用模糊匹配猜测身份。
- 同群重名、改名或识别失败会暂停该身份的自动处理，要求人工确认；必要时要求成员修改群昵称。
- 每个 scope 最多向 LLM 提供最近 `context_turns` 个完整、已发送成功的问答轮次，failed/unknown 不进入正常历史。
- 旧群共享历史保留在 shared scope，不复制到每个成员；升级后默认使用成员独立上下文。
- hybrid 明确启用后才将群公共摘要提供给成员。严格 member 模式不注入其他成员的历史。
- 数据库历史可以长期增长，但不会全部发送给模型。清空会同步取消未发送的旧任务；正在发送或状态不明的任务须先人工处理。

### 媒体

支持 JPEG、PNG、WebP、GIF 首帧，PDF、TXT、MD、DOCX，以及可可靠取得的音频或微信原生转文字结果。

- 图片：10 MiB、20 MP，最长边缩放到 2048 像素以内。
- 音频：25 MiB、最长 10 分钟。
- 聊天文档：25 MiB；每条最多 3 个附件、总计 40 MiB。
- 扫描 PDF 不做本地 OCR；无法提取时明确提示。
- 权限与群触发检查在附件获取之前；不抓屏冒充图片，不批量读取最近附件来猜测所属消息。
- UIA、复制菜单、缓存路径或转文字结果不能可靠核验时，记录 unsupported/needs_review，不伪造识别成功。

语音是否能从微信 4.1.13.12 中取得，必须在实际虚拟机验收；提供了转写接口并不意味着微信端采集已经通过。

### 知识库和工具

知识库只能通过后台上传或管理员明确提升聊天文档创建；新知识库默认不授权任何聊天。单份源文件最大 50 MiB，PDF 最多 500 页。采用 SHA-256 去重和版本化分块（默认 800 字符，重叠 120 字符），FTS5 可独立工作，embeddings 可用时增加本地向量检索和 RRF 合并。每轮最多注入 5 块、总计 6000 字符。

角色知识模式：`off` 不检索、`auto` 自动检索授权知识库、`tool` 由模型按需调用搜索。知识文本被当作不可信外部数据，不能授予权限。知识授权和工具授权独立配置。

工具默认关闭，每轮最多 4 次调用，参数上限 4 KiB、结果上限 8 KiB，执行时限 5 秒。计算器使用受限 AST，不使用 eval。旧角色若仍有「不使用工具调用」提示词，需要在角色页自行调整；升级不覆盖你的既有角色。

可选环境变量（写入 `.env`，不写入数据库）：

~~~dotenv
TRANSCRIPTION_BASE_URL=
TRANSCRIPTION_API_KEY=
TRANSCRIPTION_MODEL=
EMBEDDING_BASE_URL=
EMBEDDING_API_KEY=
EMBEDDING_MODEL=
~~~

地址/密钥留空时复用 LLM 配置；转写和 embeddings 模型名须填写服务支持的模型。更换地址或模型后重新做对应能力检查。

## 数据、迁移和回滚

- SQLite：`data/wechat_ai.db`，顺序迁移至 v10；WAL、外键、busy_timeout、事务写入。
- 每次升级前使用 SQLite backup API 备份到 `data/backups/pre-vN-*.db`，迁移后检查完整性，自动备份保留最近 10 份。
- 消息默认长期保留；聊天附件在 `data/attachments/YYYY/MM/`，默认 7 天清理；知识库源文件在 `data/knowledge/`，由管理员主动删除。
- 日志：`data/panel.log`、`data/setup.log`、`data/bot.log`。
- `.env`、`config.json`、数据库/WAL、日志、备份、附件、恢复码和真实聊天内容不得提交 Git。
- 回滚前停止 Panel 和 Bot，并备份当前数据。代码回滚和对应数据库版本恢复必须配套；不做向下迁移，也不删除数据库重建。
- `pre-vN` 是**升级到 vN 前**的备份，不是升级后的数据库。恢复前核对备份内 `PRAGMA user_version` 与目标代码版本。已推送的 Git 历史通过 revert 回滚，不强推或移动已发布标签。

## 项目结构

~~~text
panel.bat / bootstrap.py       单一启动入口、安装和环境准备
app.py / admin_api.py          运行控制台和 v1 管理 API
auth.py / auth_web.py          登录、恢复码、会话
bot.py / engine.py             单线程微信 UI、网络工作线程、消息调度
storage.py / migrations.py     SQLite 仓库与 v1→v10 迁移
schema_steps.py                各阶段表结构
permissions.py / members.py    权限、身份、群成员解析
chats.py / identity_merge.py   聊天发现、审批与身份合并
roles.py / contexts.py         角色与上下文范围
job_queue.py                  持久队列、重试、租约与人工恢复
media.py / ui_media.py         附件提取、受控微信 UI 媒体适配
providers.py                  多模态/转写/embeddings 能力检查
knowledge.py / safe_tools.py   知识库、FTS5、向量和安全工具
static/ / templates/          无 Node 构建链的管理页面
tests/                        离线自动化检查（已提交 Git）
docs/                         实施状态、统一验收清单
~~~

完整实施状态见 `docs/steps-03-11-status.md`；最终限定好友/测试群验收清单见 `docs/acceptance-steps-03-11.md`。真实微信 UI、媒体读取、模型能力、断焦点恢复以及 8/24 小时试运行均不能用离线检查代替。
